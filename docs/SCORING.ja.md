# 採点アルゴリズム

[中文](SCORING.md) · [English](SCORING.en.md) · **日本語**

本ドキュメントでは、Karaoke Battle が1回の歌唱（テイク）を基準データと比較して採点する方法を説明します。実装は
[`app/lib/scoring/`](../app/lib/scoring/)（純粋な Dart、Flutter 非依存）にあり、エントリポイントは
`Scorer.score(ScoringInput) -> ScoreResult` です。すべての数値定数は `ScoringOptions` と
`ScoringWeights` で上書きでき、以下に示すのはデフォルト値です。

## 1. 入力

| データ | 取得元 | 内容 |
| --- | --- | --- |
| 基準音符 `notes.json` | 分離後のボーカルを GAME で採譜 | 各音符の onset・offset（秒）と MIDI 音高（浮動小数点、小数を含み得る） |
| 基準 F0 曲線 `ref_f0.json` | 分離後のボーカルに SwiftF0 を適用 | 16 ms ごとの F0（Hz、0 = 無声）と信頼度 |
| 歌唱 F0 曲線 `take_f0.json` | 録音したマイク音声に SwiftF0 を適用 | 同上 |
| エネルギー曲線（任意） | take.wav と vocals.wav の RMS | 16 ms ごとの dB 値、抑揚の評価に使用 |

F0 はまず半音単位（MIDI 浮動小数点）に変換します：`midi = 69 + 12·log2(f0 / 440)`。信頼度が 0.4 未満の frame は無声とみなします。
両方の曲線を同じ 16 ms のグリッドに再サンプリングします。基準 F0 曲線がある場合、frame ごとの目標は2つあります：
**原曲の曲線**（ビブラートやスライドを含む）と **GAME 音符の音高** で、歌唱がどちらか一方に合っていれば正解とします。
つまり原曲に合わせてスライドしても正解、音をまっすぐ歌って音符の音高に留まっても正解です。基準曲線がない場合は、音符の音高のみをグリッド上でサンプリングします。
2つの目標は互いの誤差を補い合います：GAME が音高を誤って付けても原曲の曲線が残り、原曲の歌い出しのスライドが半音を超えても音符の音高が残ります。

## 2. オクターブ違いは同じ音とみなし、全体の移調を許容する

これはプロジェクトの設計上の決定です：歌い手は自分が歌いやすいキーとオクターブで歌えます。

* **chroma 距離**：2つの音高の差が `d` 半音のとき、距離は `min(|d| mod 12, 12 − |d| mod 12)` とします。
  したがって1オクターブ上や1オクターブ下で歌っても原音とまったく同じ扱いになり、距離は 0 です。
* **全曲で単一の移調量 k**：`k = 0..11` の中から Raw Chroma Accuracy が最も高くなるものを選び、
  曲全体で1つの k だけを使います。フレーズごとの変更は許可しません。許可すると、どんなにでたらめに歌っても局所的な一致が見つかってしまうためです。
* 別途「オクターブまで厳密な」移調量（−24..24 半音）と、それに対応する Raw Pitch Accuracy も計算しますが、
  **表示のみで採点には使いません**。曲全体を1オクターブ下で歌っているかどうかをユーザーが確認できるようにするためです。
* 歌唱画面のリアルタイムの色分けと、終了後の採点は同じ chroma ルール（`LiveComparator`）を使います。

## 3. 時間アライメント

1. **粗いアライメント**：有声／無声の指標で相互相関を取り、全体の遅延（±2 秒以内）を求めます。
2. **DTW による細かいアライメント**：Sakoe-Chiba 帯域幅 ±1 秒、中心は粗いアライメントの対角線上に置きます。
   局所コスト：両方とも無声なら 0、一方が有声で他方が無声なら 1、両方とも有声なら `chroma 距離 / 6`。
   対角線以外のステップには 0.5 のギャップペナルティを追加し、でたらめに歌ったテイクが時間を歪めて散発的に一致する frame を「拾う」ことを防ぎます。
3. アライメント後に k をもう一度推定し、最終値とします。
4. リズム判定（4.4）は **DTW を使いません**。全体の遅延だけを補正し、音符ごとのタイミングのずれはそのまま判定します。`AlignmentMode` は音程とその他の項目にのみ影響します。

## 4. 指標

### 4.1 Frame レベル（mir_eval `melody` の定義、許容誤差 50 cents）

| 指標 | 定義 |
| --- | --- |
| Raw Pitch Accuracy (RPA) | 基準が有声の frame のうち、歌唱が有声かつ `|take + shift − ref| ≤ 0.5` 半音（ref は原曲の曲線または音符の音高のいずれか）である割合（表示のみ） |
| Raw Chroma Accuracy (RCA) | 同上だが chroma 距離を使用、**主要な音程指標** |
| Voicing Recall | 基準が有声で、歌唱も有声である割合 |
| Voicing False Alarm | 基準が無声なのに、歌唱が有声である割合 |
| Overall Accuracy | 両方とも無声、または両方とも有声かつ chroma が正しい frame の割合 |

### 4.2 音符レベル（デフォルト：基準音符ガイド方式）

GAME は音節ごとに音符を区切りますが、連続する音節は同じ音高であることが多く、F0 だけで区切るとそれらが1つにまとまってしまいます。そのためデフォルトでは歌唱 F0
から音符を区切らず、**各基準音符をそれ自身の時間範囲内で評価**します：

* **一致 frame**：歌唱が有声で、基準曲線**または**音符の音高との chroma 距離が 50 cents 以内（音符範囲外の延長区間では音符の音高のみを見るため、隣接する音符がこの音として数えられることはありません）。
* **音高ヒット**：一致 frame が音符範囲の 50% 以上をカバーしていること。
* **歌唱の onset / offset**：`[onset − 100 ms, offset + 100 ms]` の範囲内で、音符との重なりが最も大きい一致区間を探し
  （最大 3 frame の途切れを許容）、その区間の境界を歌唱の始点・終点とします。探索窓は休符側にのみ延長し、
  隣接する音符の範囲には入りません（音と音の間のスライドは遷移とみなします。次の音に早く入った場合は、前の音の offset 誤差に反映されます）。
* **期待される onset / offset**：基準曲線がある場合は同じ方法で原曲の曲線上で測定するため、原曲の歌い手本人が歌えば満点になります。
* **onset ヒット**：`|onset 誤差| ≤ 50 ms`。**offset ヒット**：onset と音高の両方がヒットし、かつ
  `|offset 誤差| ≤ max(50 ms, 20% × 音符の長さ)`。
* 基準曲線がその音符内で完全に無声である音符は、評価不能としてマークし除外します。
* Precision の分母には、「誤って歌った音符または正しく歌った音符」に加えて「すべての音符の外側にある歌唱の有声区間」（誤検出）を含みます。

出力は3組の precision / recall / F1（onset のみ、onset + 音高、onset + 音高 + offset）と、
各音符のレポート（ヒットの有無、cents 偏差の中央値、onset/offset 誤差、カバー率）です。
`NoteSegmentation.fromTakeF0` を使うと、歌唱 F0 から音符を区切ってから二部グラフマッチングを行う mir_eval `transcription` 方式に切り替えられます。

### 4.3 テクニック指標

**ロングトーン**（基準音符 ≥ 400 ms）のみで分析し、歌唱側は時間伸縮していない元の frame を使います。

* **ビブラート (vibrato)**：音高曲線のトレンドを除去し、Hann 窓をかけて、3〜9 Hz の範囲を 0.05 Hz の分解能で DFT します。
  約 0.5 秒の分析窓をビブラートありと判定する条件：レート 4〜8 Hz、ピーク・トゥ・ピーク振幅 30〜150 cents、
  周期性（正弦波エネルギー / トレンド除去後の分散）≥ 0.35。各ロングトーンの「ビブラート量」= 条件を満たした分析窓の割合です。
* **安定感 (stability)**：ビブラート1周期分（検出できない場合は 6 Hz とみなす）の移動平均でビブラートを取り除いた後の、
  中央値に対する音高の標準偏差（cents）。原曲の曲線についても同じ値を計算し、基準とします。
* **ロングトーン (long tone)**：ロングトーン範囲内で、歌唱が有声かつ目標との差が 50 cents 以内である frame の割合。
  基準が有声の frame のみを数えます。
* **抑揚 (expression)**：基準が有声の frame における、アライメント後の歌唱と基準のエネルギー曲線（dB）の Pearson 相関係数。

### 4.4 リズム判定（音ゲー方式）

maimai、CHUNITHM、太鼓の達人などの音楽ゲームにならい、基準の各音符の歌い出しと歌い終わりの誤差を段階に分け、段階ごとに決まった割合の点を与えます。

| 判定 | 判定幅（120 BPM） | 得点 |
| --- | --- | --- |
| PERFECT | ±50 ms | 100% |
| GREAT | ±100 ms | 70% |
| GOOD | ±150 ms | 40% |
| MISS | 範囲外、またはその音を歌っていない | 0% |

* **テンポに応じた拡縮**：判定幅に `120 / BPM` を掛け、0.75〜1.5 倍に制限します。速い曲ほど厳しく、遅い曲ほど緩くなります。BPM はユーザーの手動設定、なければ Beat This! の検出値を使い、どちらもない場合は 120 BPM の判定幅を使います。
* **歌い終わり**：同じ 3 段階ですが、ロングトーンでは判定幅を音の長さの 20%／40%／60%（大きいほう）まで広げます。歌い出しが MISS の場合は歌い終わりを判定しません。
* **音符ごとの得点** = 0.7 × 歌い出し + 0.3 × 歌い終わり。リズムの項目別スコアは評価可能な全音符の平均です。
* **アライメント**：全体のずれ 1 つだけを使い、DTW は使いません。音符ごとのずれが吸収されないようにするためです。遅延を測定済み（設定の「遅延を測定」）の場合は録音時のクロックをそのまま信頼し、曲全体が一様に早い・遅い場合も判定に含めます。ただし推定された全体のずれが ±150 ms を超える場合は、測定値が合っていない（デバイスを変えたなど）とみなして推定値を使います。未測定の場合は常に推定値を使います。
* **走り／タメの傾向**：ヒットした音符の歌い出し誤差の中央値が −25 ms 以下なら走り、+25 ms 以上ならタメ、それ以外は安定とします。録音クロックを信頼した場合のみ表示します（DAM 精密採点の「走り」「タメ」を参考）。

## 5. 項目別スコアと総合得点

すべての項目別スコアは `[0, 1]` の範囲にあり、マッピングはすべて単調です。`clamp` は `[0, 1]` の範囲に収めることを表します。

| 項目別スコア | 式 | 評価不能時 |
| --- | --- | --- |
| 音程 pitch | `clamp((RCA − 0.2) / 0.75)` | 常に評価可能 |
| リズム rhythm | 評価可能な全音符の `0.7·歌い出し判定 + 0.3·歌い終わり判定` の平均。判定の得点は PERFECT 1、GREAT 0.7、GOOD 0.4、MISS 0（4.4 を参照） | 評価可能な音符がない → 0 |
| 安定感 stability | `clamp(1 − max(0, std − refStd) / 50)`、std は歌唱のロングトーンの平均標準偏差、refStd は原曲の同じ値 | 基準にロングトーンなし → 除外、歌唱に分析可能なロングトーンなし → 0 |
| ビブラート vibrato | `clamp(amount / target)`、amount は歌唱のロングトーンの平均ビブラート量、`target = min(原曲のビブラート量, 0.4)` | 基準にロングトーンなし、または原曲がほとんどビブラートを使わない（量 < 0.25）→ 除外 |
| 抑揚 expression | `clamp(r / 0.8)` | いずれかのエネルギー曲線が欠けている → 除外 |
| ロングトーン long tone | ロングトーンの平均達成率 | 基準にロングトーンなし → 除外 |

デフォルトの重み：音程 40、リズム 20、安定感 10、ビブラート 10、抑揚 10、ロングトーン 10。

```
total = 100 × Σ(wᵢ · sᵢ) / Σ(wᵢ)      「評価可能」な項目別スコアのみを合計し、重みは自動で再正規化
```

| 総合得点 | ランク |
| --- | --- |
| ≥ 97 | SSS |
| ≥ 92 | SS |
| ≥ 85 | S |
| ≥ 75 | A |
| ≥ 60 | B |
| ≥ 40 | C |
| その他 | D |

## 6. キャリブレーション結果

実際の楽曲（30 秒の CC-BY クリップ）からエンジンが生成した notes.json と ref_f0.json で検証しました。
固定サンプルは [`app/test/scoring/fixtures/`](../app/test/scoring/fixtures/) にあります：

| 歌唱 | 総合得点 | ランク |
| --- | --- | --- |
| 原曲自身の F0 曲線 | 100.0 | SSS |
| 原曲を 9 半音下げ（3 半音上げて 1 オクターブ下げたのと同等）、さらに 300 ms 遅延 | 100.0 | SSS（k = 9） |
| ランダムな音高 | 8.9 | D |

5 分の曲（約 19,000 frame、650 音符）の採点にかかる時間は約 150 ms です。

## 7. 既知の制限

* 基準 F0 曲線がない場合、期待される onset は GAME の音符境界から取られ、目標は音符の固定音高になるため、
  F0 トラッキングの遅延や自然な音高の揺れによってわずかに減点されます。
* 別の音のすぐ後で次の音に早く入った場合、その時間は前の音の範囲に属するため、早く入った量が小さめに測られることがあります。休符の後の走りは測定できます。
* 遅延が未測定の場合、曲全体が一様に早い・遅いずれは遅延とみなして補正され、リズムの減点も走り／タメの判定もありません。
* ビブラートは、原曲自体がビブラートを多用している楽曲でのみ採点されます。それ以外の楽曲では残りの5項目で採点します。
* 歌詞は採点しません（中国語・日本語の歌詞に伴奏のかぶりが加わると音声認識の誤差が大きすぎ、得られるスコアに意味がないためです）。

## 8. 参考文献

指標の定義は mir_eval（Raffel et al., ISMIR 2014）の `melody` および `transcription` モジュールに従います。
RPA / RCA の 50 cent の許容誤差とオクターブ等価は Poliner et al. 2007 および Salamon et al. 2014 に、
DTW の帯域幅制限は Sakoe & Chiba 1978 に基づきます。完全な引用と BibTeX は [CITATIONS.md](CITATIONS.md) を参照してください。
